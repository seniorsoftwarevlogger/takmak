# Takmak + ST7789 76×284

Экспериментальные shield для SuperMini nRF52840 / `nice_nano_v2`. Варианты собраны 13 октября 2026. Донгл и предыдущий горизонтальный тест левой половинки проверены пользователем. Новая вертикальная версия с тремя страницами собрана и прошита на тестовую SuperMini; пользователь подтвердил вертикальное отображение и переключение всех трёх страниц замыканием 008–GND. Полноценная левая матрица с TFT физически ещё не проверена.

Проверенный UF2 для возврата сохранён в Git: [checkpoint 2026-10-13](checkpoints/2026-10-13-portrait/README.md), рядом контрольная сумма. Каталог `artifacts/` остаётся локальным для текущих сборок и логов.

## Быстрый тест левой половинки без переноса проводов

`takmak_tft_left_bench` — вариант по запросу пользователя: сохранить нынешнюю проводку работающего TFT, а разводку матрицы решить позже. Роль — левая центральная половинка, одна правая BLE-половинка. Экран вертикальный, 76×284: страницы «Статус», «Управление» и «Топография» с данными ZMK. SPI1 обслуживает TFT, SPI3 оставлен RGB. Питание экрана постоянно включено.

**Локальная матрица полностью отключена**, вместо неё выбран mock-сканер с пустым списком событий. Это исключает конфликт её GPIO с дисплеем. Проверка экрана таким способом не подтверждает совместную работу TFT с левой матрицей; для этого нужен отдельный вариант `takmak_tft_left` с новой проводкой или будущий регистр. Левый энкодер и RGB используют прежние непересекающиеся пины, RGB выключен при старте.

Текущая проводка: **CLK→113, DIN→010, CS→009, DC→031, RES→029**, VCC→3.3 V, GND→GND, BL→GND. Перенос на 020/017/008/P1.01/P1.02 для этого теста НЕ требуется.

Сборка: `./build.sh takmak_tft_left_bench`. UF2: `artifacts/takmak_tft_left_bench.uf2`.

### Переключение страниц

- На макетке — нормально разомкнутая кнопка **008 (P0.08) ↔ GND**. Включена внутренняя подтяжка; внешний резистор не требуется. Можно проверять кратким замыканием перемычкой.
- В варианте с настоящей матрицей — нажатие левого энкодера (позиция 36, строка 2 / колонка 6 с нуля) на всех пяти слоях. Behavior `&tft_mode` можно перенести на другую клавишу.
- Порядок: **Топография → Статус → Управление → Топография**. При включении всегда топография, режим не записывается во flash.
- Временная кнопка фильтрует дребезг 30 мс, удержание не повторяет переключение. Её GPIO отсутствует в полной левой сборке: там P0.08 уже занят TFT CS.
- Поворот левого энкодера сохраняет регулировку яркости RGB; нажатие больше не выполняет прежние RGB-команды в экспериментальной раскладке. Исходный модуль клавиатуры не изменён.

Текущая сборка: FLASH 373116 B (46.01%), RAM 138000 B (52.64%). Структура UF2 и devicetree проверены. Матрица отключена, TFT остаётся на прежних пинах. Вертикальная версия прошита 13 октября 2026 на тестовую SuperMini (USB serial `71AB9D85A511C2EF`). После перезапуска подтверждены USB `Takmak TFT Left` и работающий журнал ZMK. UF2 SHA256: `7acab75de536a2ae08aa8e4bf3182fd848922213eb602636c3166ac7077a97ca`. Пользователь подтвердил: всё видно, экран вертикальный, все три страницы переключаются замыканием 008–GND. Удержание кнопки и физическое нажатие энкодера отдельно ещё не проверялись.

Предыдущая горизонтальная версия `TAKMAK / left test` была прошита на эту плату и подтверждена пользователем. Для возврата сохранена `artifacts/takmak_tft_left_bench-landscape-verified.uf2`. Подключение правой половинки не проверялось.

## Левая половинка

`takmak_tft_left` — центральная левая половинка с настоящей матрицей 5×7, левым энкодером EC11 и одной правой BLE-половинкой. TFT использует SPI1, RGB остаётся на SPI3/P0.06. Матрица, physical layout, энкодер и RGB-схема включены из соседнего модуля `../zmk-keyboard-takmak/`; держать эти каталоги рядом.

Это вариант для прямого подключения центральной левой половинки к компьютеру (USB/BLE), а не peripheral для отдельного донгла. Правую рабочую половинку и её BLE-привязки в ходе подготовки не меняли.

### Новая проводка TFT

Отключить питание перед перестановкой проводов. Маркировка относится к SuperMini, не к номерам Arduino Dn. Питание и BL остаются такими же, как в работающем цветовом тесте.

| TFT | Было в тесте донгла | Левая половинка | Что используется |
|---|---|---|---|
| CLK / SCL | 113 / P1.13 | **020 / P0.20** | бывший OLED SCL |
| DIN / SDA | 010 / P0.10 | **017 / P0.17** | бывший OLED SDA |
| CS | 009 / P0.09 | **008 / P0.08** | свободный SERIAL |
| DC | 031 / P0.31 | **P1.01** | дополнительная площадка SuperMini |
| RES | 029 / P0.29 | **P1.02** | дополнительная площадка SuperMini |
| VCC | VCC 3.3 V | VCC 3.3 V | P0.13 HIGH включает внешний регулятор |
| GND | GND | GND | общая земля |
| BL / BLK | GND | GND | у проверенного модуля подсветка активна при LOW |

Все пять старых сигнальных GPIO заняты матрицей: P1.13 — строка 2, P0.10 — строка 4, P0.09 — строка 5, P0.31 — колонка 3, P0.29 — колонка 2 (нумерация с единицы в левом overlay). Поэтому прошивать полноценную левую половинку с прежней проводкой экрана нельзя: экран окажется подключён к сканируемой матрице.

Новая конфигурация сохраняет все строки, колонки, энкодер и RGB. Регистр сдвига для этого варианта не нужен. Нужен доступ к двум дополнительным GPIO и отдельные провода; штатный разъём OLED сам по себе всех сигналов TFT не содержит. Два контакта I²C используются как SPI, поэтому прежний OLED отключён.

Дополнительные площадки SuperMini расположены иначе, чем у nice!nano: ориентироваться на распиновку своей платы. Источники: [документация SuperMini](https://wiki.icbbuy.com/doku.php?id=developmentboard:nrf52840), [footprint из официального PCB-файла](https://github.com/BlueDrink9/supermini-nrf52840-kicad), [распиновка поставщика](https://kriscables.com/supermini-nrf52840/).

### Что показывает экран

Общий портретный интерфейс обеих левых сборок:

1. **Статус:** выбранный выход USB / BT-профиль, активный слой, батареи L/R, WPM и яркость RGB.
2. **Управление:** крупная яркость RGB, полоса уровня, ON/OFF, слой и батареи.
3. **Топография:** контуры из реального silkscreen платы, TAKMAK, выход, батареи и слой.

Данные поступают из API ZMK. До первого сообщения правой батареи — `--`; после отключения остаётся последнее значение. Локальная оценка заряда зависит от штатного датчика nice_nano_v2 и не проверена с аккумулятором этой платы. Значение яркости показывается и при выключенном RGB, рядом указан OFF. WPM требует событий клавиш; на макетке локальная матрица выключена.

TFT: RGB565, SPI 1 MHz, вертикальная область **76×284**, смещения **82/18**, MADCTL **0x00**. После инициализации отправляется INVOFF (0x20), как требовал работающий цветовой тест. LVGL canvas перерисовывается только при изменении данных; снимок данных проверяется раз в 200 мс. Подписи рисуются bitmap-шрифтом, топография взята из `scene/public/decoration/takmak-contours.svg`.

Экран и внешнее питание постоянно включены, сон отключён для проверки. Это тестовая конфигурация: автоматическое выключение/пробуждение и расход батареи ещё не проверены. RGB скомпилирован и доступен из исходной раскладки, но выключен при старте. Одновременная работа реальных RGB, матрицы и TFT ещё требует проверки на железе. Переключение внешнего питания и Studio unlock заменены на `&none`, чтобы не выключить TFT; Studio в этой сборке не включён.

### Результат сборки и проверки

- Левая половинка: FLASH 375816 B (46.34%), RAM 138256 B (52.74%).
- Донгл после переноса модуля в репозиторий также собирается: FLASH 378264 B, RAM 93360 B.
- `scripts/check_left_pins.py` проверяет скомпилированный `edt.pickle`: настоящая матрица 5×7, включённый энкодер, разные SPI-контроллеры TFT/RGB, отключённые OLED/I²C/UART и отсутствие пересечений 21 используемого GPIO (включая питание).
- Проверена структура обоих UF2, family 0xADA52840 и адреса приложения без перезаписи загрузчика.
- Два предупреждения закреплённого Zephyr: устаревшие NFCT_PINS_AS_GPIOS и NRF_STORE_REBOOT_TYPE_GPREGRET.
- Отрисовка трёх страниц проверена отдельным host-тестом с AddressSanitizer/UBSan: заряд −1…100, яркость 0…100, WPM 999, длинные названия слоя. Предпросмотр с примерными значениями — `artifacts/portrait-firmware-preview.png`.
- Физическая проверка полного левого варианта ожидает переподключения экрана; bench проверяется на прежних проводах.

### Проверка после переподключения

1. На тестовой SuperMini перенести сигнальные провода согласно таблице. Рабочую собранную клавиатуру не перепрошивать для первого теста.
2. Дважды кратко замкнуть RST–GND, дождаться диска NICENANO. Прошить `artifacts/takmak_tft_left.uf2`.
3. Убедиться, что USB определяется как `Takmak TFT Left`, текст расположен вертикально, топография помещается, нажатия энкодера переключают три страницы по кругу.
4. Для проверки матрицы на отдельной макетке кратко соединить 115 (строка 1) с 002 (колонка 1): ожидается первое нажатие исходной раскладки (`GRAVE`) в документе. Делать это только после переноса всех проводов TFT; открыть пустой текстовый документ для проверки ввода. На настоящей PCB вместо перемычки нажать соответствующую клавишу.
5. Проверить переключение слоёв, энкодер, затем RGB и связь с правой peripheral-половинкой. Сброс существующих BLE-привязок отдельно не выполнялся.

## Сборка

Требуются Docker Desktop и несколько гигабайт места для SDK/исходников. `manifest/west.yml` фиксирует ревизии всех зависимостей; Docker-образ закреплён digest. ZMK ccf20a1f5c1534a197d32279abbe0eaf651099d8, Zephyr dacab4875df72109b96cc8977547a0dc04875bcd, SDK 0.16.9.

Из этого каталога:

```sh
./build.sh takmak_tft_left
# либо прежний донгл:
./build.sh takmak_tft_dongle
```

По умолчанию создаётся отдельный workspace `$HOME/.cache/takmak-zmk-tft`; другой пустой каталог задаётся через `TAKMAK_TFT_WORKSPACE`. Скрипт не подменяет manifest существующего другого проекта. UF2 сохраняются в `artifacts/` (игнорируются Git), рядом находятся контрольные суммы и диагностические материалы текущей сборки.

Фактически выполненная сборка этой итерации использовала существующий SDK/workspace `/Users/dima/.cache/codex-zmk/takmak-tft-2026-10-13` и отдельные каталоги `build/takmak_tft_left`, `build/takmak_tft_left_bench`, `build/takmak_tft_dongle_repo`. Новые исходники и UF2 уже находятся в основном репозитории на 4T; сборочные зависимости оставлены в кэше внутреннего диска.
