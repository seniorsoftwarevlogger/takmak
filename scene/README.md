# Takmak scene

Первая локальная интерактивная сцена для выбора ракурса будущего сайта. Два исполнения: белое низкопрофильное с оранжевыми крутилками и чёрное стандартное. Можно переключать исполнение или показать оба. Интерфейс оформлен на чистом белом фоне: нейтральная серая типографика, тонкие разделители, сдержанные элементы управления. Оранжевый акцент оставлен крутилкам и индикаторам фокуса.

## Запуск

Из этого каталога:

```sh
npm ci
npm run dev
```

Адрес по умолчанию: http://127.0.0.1:5173. Если порт занят, Vite напечатает другой адрес. Зависимости проверены с Node 22.17.0. Сцена работает локально; публикация не выполнялась. После установки для просмотра не нужны внешние CDN или шрифты.

Для production-сборки: `npm run build`. Результат находится в `dist`; обслуживать его HTTP-сервером, не открывать HTML через `file://`.

## Управление

- Перетаскивание сцены вращает камеру, колёсико приближает и отдаляет, правая кнопка перемещает цель камеры. На сенсорном экране — жесты OrbitControls.
- «Левая» / «Правая» выбирает половинку для настройки разворота, наклона и крена. Расстояние между половинками и высота левой регулируются отдельно.
- Положения половинок общие для двух профилей; это позволяет сравнивать их в одной композиции.
- «¾», «Сверху», «Спереди» устанавливают камеру и вписывают видимую сборку. На узком экране кнопка фронтального вида скрыта.
- «Зафиксировать ракурс» сохраняет положение камеры, профиль и параметры половинок в localStorage и скачивает `takmak-<profile>-pose.json`.
- «Мой ракурс» восстанавливает сохранённую композицию. Она также восстанавливается при перезагрузке. «Сбросить» возвращает начальную композицию без удаления сохранённой.
- PNG экспортирует текущий холст с прозрачным фоном. Панель управления в PNG не попадает.

Передай сохранённый JSON для следующей итерации — там есть точные значения ракурса. Локальное сохранение привязано к браузеру и адресу сервера; скачанный файл остаётся переносимым.

## Геометрия и происхождение

`public/models` содержит 11 GLB, заново полученных из предоставленных STEP в `../3d models/step`, а не изменённые исходники. В каждом GLB одна геометрия тела вместо сотен отдельных CAD-граней. Суммарно 73 494 треугольника для всех альтернативных деталей корпуса и крутилок.

`manifest.json` содержит контрольные суммы STEP, исходные габариты и пути. Координаты GLB — метры; сцена и её параметры работают в миллиметрах. Низкие верхние части сдвинуты на −150 мм по исходной оси Y, чтобы совместить их с нижними частями. Для низкопрофильной сборки нижние части вместе с reset-кнопками подняты на 2 мм: верх дна в STEP находится на Z=−4 мм, а низ верхней части — на Z=−2 мм. Это устраняет зазор в сцене. Для стандартного профиля сдвиг равен нулю. Нижние части и reset-кнопки сохраняют взаимные координаты CAD.

`layout.json` получен из замкнутых контуров отверстий под свитчи в STEP Regular Top. Для согласованной комплектации используются 30 клавиш слева и 37 справа плюс один энкодер на каждой половинке. Левая длинная клавиша и правые отдельные клавиша/энкодер выбраны по фото и уточнениям владельца. Правый блок привязан к центру квадратного отверстия под альтернативную 2u-клавишу (23,714; −29,582 мм): два центра 1u расположены вдоль его оси ±9,525 мм. Это заменяет ручные координаты с чрезмерным расстоянием 24,04 мм; вырезы стабилизатора не используются как центры переключателей. Получаются кнопка (28,4770; −37,8307) и энкодер (18,9519; −21,3330). Посадки в Low Top совпадают после сдвига Y на −150 мм. Это привязка визуализации к корпусу, а не производственная проверка PCB: текущая плата немного отличается от STEP. Число отображаемых клавиш не является BOM или количеством позиций firmware transform.

Пересоздание геометрии и проверка:

```sh
npm run assets
npm run check
npm run build
```

Генератор использует occt-import-js/OpenCascade, а извлечение контуров — Python 3 без сторонних библиотек. Исходные STEP не изменяются.

## Границы первой итерации

- Кейкапы — процедурные визуальные приближения MBK и Cherry profile; точные CAD-модели не предоставлены. Подписи ориентируются на фото, но японские сублегенды не воспроизведены.
- Свитчи представлены упрощёнными видимыми корпусами. Это не точные CAD-модели Kailh MX/Choc.
- Экраны обеих сборок воспроизводят показанный на фото статус ZMK: USB, зарядка 100%, слой Base и WPM 0. Это статичная пиксельная текстура 128×32, а не текущие показания клавиатуры. По уточнению владельца экран включён и в низкопрофильной версии.
- PCB, аккумуляторы, проводка, крепёж и сам внешний донгл не включены. Explode view внутренней электроники не реализован.
- Геометрическое вписывание кейкапов и крутилок предназначено для визуализации; производственная проверка посадки и зазоров не проводилась.
- Последняя изготовленная плата — 3.0, проект 3.1 ещё не изготовлен. Сцена не заявляет проверенную совместимость корпуса с 3.1.

## Проверка

Проверены переключение обоих профилей и их совместный показ, поворот камеры мышью, масштаб, независимость настроек половинок, скачивание JSON и PNG, сброс и восстановление ракурса, сохранение после перезагрузки. Автоматическая проверка сверяет хеши STEP, структуру и конечность координат GLB, габариты и уникальность посадок клавиш. Production-сборка проходит.

Исходники интерфейса: `src/main.js`, `src/style.css`, `index.html`. Скрипты подготовки: `scripts/prepare-assets.cjs`, `scripts/extract-layout.py`. Внешние модели свитчей не включены в сцену. Условия использования исходной аппаратуры остаются указанными в основном README репозитория.

## Ракурсы и топографический рисунок

Кнопка «Ракурсы 06» открывает сетку сравнения. Первые два варианта загружаются из предоставленных автором JSON (`assets/poses/user-01.json` и `user-02.json`); второй — предпочтение автора. Четыре дополнительных варианта задаются в `loadPoseOptions()` на основе второго. Карточка переносит положения половинок и направление камеры в основную сцену, затем вписывает клавиатуру в текущий размер окна; сохранение в браузер происходит только по кнопке «Зафиксировать ракурс». Закрытие галереи сохраняет предыдущее положение сцены.

Превью рендерятся последовательно одним WebGL-рендерером при одинаковых свете, размере 720×480 и увеличении 1,3× для удобства сравнения. Увеличение относится только к карточкам и сетке PNG; координаты камер в исходных JSON не меняются. Сетку можно скачать кнопкой в галерее. Прямая ссылка: `http://127.0.0.1:5173/?gallery=1`.

Исходный рисунок автора сохранён без изменений в `assets/decoration/takmak-silkscreen.dxf`. Скрипт `python3 scripts/extract-decoration.py` преобразует его 43 плоских SPLINE и 13 LINE в SVG, с 24 отсчётами на ненулевой узловой интервал сплайна. `public/decoration/takmak-full.svg` сохраняет все эти объекты; `takmak-contours.svg` содержит только кривые для оформления сайта. Источник, хеш и границы записаны в `source.json`. Рисунок использован как лёгкий фон сцены и иллюстрация истории названия в галерее. PCB и исходный DXF не редактировались.

## Выбранная композиция и парение

Основной ракурс — второй JSON автора (`user-02.json`). Он загружается по умолчанию, используется кнопками сброса и «¾», с вписыванием под размер окна. Новые сохранения используют ключ localStorage `takmak.scene.pose.v2`; прежние сохранения v1 не удаляются.

Лёгкое парение добавляет каждой половинке вертикальное отклонение до ±1,6 мм и покачивание до 0,35° с периодами 7,5 и 9 секунд. Движение не меняет исходные параметры ракурса и не накапливает смещение. Выключатель «Лёгкое парение» возвращает точную базовую позу; при prefers-reduced-motion движение выключено по умолчанию. Галерея остаётся статичной для сравнения. При скрытой вкладке и открытых диалогах анимация приостанавливается.

## Контурный рендер

Переключатель «Контуры / Студийный» в панели композиции сравнивает новую техническую иллюстрацию с прежним светом. По умолчанию включены контуры; выбор сохраняется отдельно от JSON ракурса. Основной второй ракурс и парение сохраняются.

В `src/technical-lines.js` соседние треугольники объединяются по общим координатам. Показываются резкие грани от 28° и силуэты, зависящие от камеры; копланарные рёбра не выводятся. Проверка глубины скрывает обратные линии. Геометрия линий переиспользуется между одинаковыми кейкапами. Это интерактивный рендер настоящей сцены, а не обработка картинки.

В контурном режиме свет нейтральный, белые поверхности светлее, блики ослаблены. Оранжевые крутилки, графит стандартного корпуса и экран сохраняют цвет. Фоновая топография скрыта только в этом режиме. Галерея и PNG используют выбранный стиль; имя PNG содержит `technical` или `studio`.

### Адаптация контуров к масштабу

«Адаптивные контуры» включены по умолчанию и сохраняются отдельно в localStorage. На общем плане у каждого кейкапа остаётся непрерывный верхний контур; соседняя линия фаски и остальные второстепенные грани затухают. У CAD-деталей сохраняются силуэты и основные резкие грани. При увеличении детали плавно возвращаются: переход настроен на 3–7 CSS-пикселей на миллиметр модели (примерно 54–126 px на ширину клавиши 18 мм). Считается экранный масштаб каждой грани, а не только расстояние до камеры: учитываются FOV, zoom, размер области рендера и масштаб сборки. Плотность пикселей экрана не меняет пороги.

Отключение переключателя возвращает прежнюю постоянную детализацию. В студийном режиме переключатель недоступен. Параметры обновляются перед рендером линий, поэтому PNG и превью ракурсов также получают детализацию под свой размер. Проверены общий план, приближение с возвратом деталей, сравнение on/off и отсутствие ошибок WebGL в браузере. `npm run check`, проверка синтаксиса `technical-lines.js` и production-сборка проходят.


Скрытые посадочные места больше не подтягиваются поверх корпуса постоянным смещением глубины в NDC. Линии используют небольшой сдвиг 0,04 мм в координатах камеры, независимый от расстояния. Основной периметр кейкапа явно задан верхним кольцом процедурной геометрии; он не исчезает вместе с линией фаски. При близком рассмотрении возвращаются второстепенные линии.

## Пиксельный OLED

`public/textures/oled-status.png` — исходная текстура 128×32; SVG рядом позволяет рассмотреть пиксели крупно. `oled-status.json` используется в сцене: поворот на −90°, чёткие пиксели при приближении и mipmaps при удалении. Активная область 5,6×22,4 мм помещена в видимый вырез STEP 8,5×24 мм, смещённый относительно выемки модуля на (+0,5; +1) мм.

Рисунок восстановлен по фото и расположению виджетов в локальном `zmk/app/src/display/status_screen.c`. Глифы Montserrat/Font Awesome взяты из локальных таблиц LVGL (16 px, слой 12 px), переведены из 4 bpp в монохром порогом 8. Точное совпадение с бинарной прошивкой не заявляется. Перегенерация: `python3 scripts/prepare-oled.py /path/to/lvgl`. В обычной сборке внешний LVGL не нужен; лицензия сохранена рядом с текстурами.

## Основной сайт и техническая студия

Главная страница `/` — сайт Takmak: два исполнения, реальное фото, топография
из DXF, руководство по сборке и скачиваемые архивы. `/studio.html` сохраняет
редактор ракурсов, галерею, экспорт JSON/PNG и все параметры сцены.

Главная показывает ту же геометрию через `/studio.html?embed=1` в выбранном
втором ракурсе. В этом режиме редактор скрыт, камера фиксирована, сохранённые
ракурсы студии не подмешиваются. Переключение профилей и парение управляются
сообщениями только от родительской страницы того же origin. За пределами
видимой области анимация останавливается; reduced motion учитывается.

`python3 scripts/prepare-downloads.py` формирует два ZIP корпуса (оригинальные
STEP и STL из проверенных GLB, мм), ZIP исходников KiCad 3.1 и SHA-256-манифест.
Это явный набор файлов, без Git-метаданных, временных данных и локальных путей.
Полный BOM, производственный комплект 3.0, карта пайки и проверенные бинарники
прошивки ещё отсутствуют; на сайте отмечены соответствующие ограничения.

Vite собирает `index.html` и `studio.html`. Сайт пока локальный.

## Уточнения позиционирования и комплектации

Главный заголовок: No Compromise 65% Split Keyboard. Главное преимущество —
полная русская раскладка, включая «Ъ», без переноса букв на другие слои,
с минимумом изменений относительно привычного расположения. Утверждение
об исключительности среди всех сплитов на сайте не используется.

По уточнению автора Choc v1/MBK и Kailh MX/Cherry — примеры его сборок.
Низкая версия допускает Choc v2; кейкапы выбираются под свитчи, посадки
сверяются с конкретной ревизией. Цвет корпуса произвольный, правый энкодер
опционален. Оба профиля допускают отдельный донгл или левую центральную
половинку в зависимости от прошивки. На одну клавиатуру автор указал 2 × SuperMini nRF52840
или другие совместимые с nice!nano контроллеры и 2 × EEMB 383454LC LiPo
3,7 В, 720 мА·ч с разъёмом JST. По одному на половинку; отдельный донгл
не входит в эти два контроллера. Предварительный ориентир толщины до 2 мм отменён. Универсальная плата позволяет из партии пяти собрать две клавиатуры
и оставить одну плату запасной; минимальный заказ у производителя не утверждается.

На главной странице камера стартует на 18% крупнее относительно полного
вписывания сцены. Перетаскивание мышью вращает модель, колёсико меняет масштаб;
панорамирование отключено. Панели ракурса доступны только в студии.

Область WebGL на главной занимает ширину страницы и выходит на 120 px выше
и ниже блока модели. Смещение проекции сохраняет исходный масштаб в центре;
контентная колонка больше не обрезает модель при зуме и вращении.

## GitHub Pages

Публичный адрес: https://seniorsoftwarevlogger.github.io/takmak/
Workflow корня `.github/workflows/pages.yml` выполняет проверку ассетов,
подготовку скачиваний и Vite build с `PAGES_BASE_PATH=/takmak/`, затем публикует
`scene/dist` после push в `master`. В PR выполняется только сборка и проверка.
`verify-site.py /takmak/` проверяет ссылки HTML/CSS, динамические ресурсы сцены
и хеши архивов. Пути исходных STEP в manifest относительны корню репозитория.
